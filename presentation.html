Транзакции и алгоритмы

Конвейер POST /api/bookings и защита от гонок

401 Auth
Bearer-токен проверяется до чтения JSON-тела
400 Input
Поля, типы, шаг 30 мин, часы 09–18, не прошлое
404 Room
Проверка, что аудитория существует в таблице rooms
BEGIN IMMEDIATE
Блокировка записи SQLite до проверки конфликтов
409 / 201
Нет пересечения — INSERT и возврат Booking

Почему BEGIN IMMEDIATE

Обычный SELECT перед INSERT при параллельных запросах пропускает оба потока. BEGIN IMMEDIATE ставит запись в очередь на уровне драйвера SQLite: первый фиксирует бронь (201), остальные видят её и получают 409.

Линейный расчёт free-slots

Активные интервалы за дату обрезаются по [540, 1080] минутам и сортируются. Один проход курсором от 09:00 до 18:00 даёт максимальные окна и не создаёт пустых слотов на стыках.

Контракт ошибок и крайние случаи

Единый JSON и 4 неочевидных кейса

{
  "code": "BOOKING_CONFLICT",
  "message": "Аудитория уже забронирована на это время",
  "details": {
    "roomId": 1,
    "date": "2026-11-16",
    "startTime": "12:00",
    "endTime": "13:00"
  }
}

Коды: VALIDATION_ERROR (400), UNAUTHORIZED (401), FORBIDDEN (403), ROOM_NOT_FOUND / BOOKING_NOT_FOUND (404), BOOKING_CONFLICT / ALREADY_CANCELLED (409), INTERNAL_ERROR (500).

01
Авторизация раньше валидации тела FastAPI-парсер Body срабатывает до Depends. Читаем JSON вручную, чтобы пустой POST без токена отдавал 401, а не 400.
02
Отсев bool в числовых полях В Python isinstance(True, int) истинно — проверяем строго через is_strict_int.
03
Админ в пользовательской отмене DELETE /api/bookings/{id} даёт 403 даже админу на чужой брони; чужие снимаются через /api/admin/bookings/{id}.
04
Чистый UTF-8 и перехват 422/500 Utf8JSONResponse отдаёт кириллицу без \uXXXX; 422 переводится в 400, 500 скрывает stacktrace.
